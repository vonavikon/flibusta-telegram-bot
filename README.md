# flibusta-telegram-bot

Telegram-бот для поиска и скачивания книг с [Flibusta](https://flibusta.is).

LLM (GLM-4.5 через z.ai) делает ровно одну вещь — превращает свободный запрос в структуру «автор + название», чтобы OPDS-поиск Flibusta попадал точно. Поиск, ранжирование и скачивание — детерминированные, без LLM.

## Возможности

- Поиск свободным текстом («конан дойл шерлок») — LLM разбирает автора и название
- Ранжированный список: форматы, размер, число скачиваний, переводчик
- Карточка книги с описанием и кнопками форматов (fb2, epub, mobi, pdf, txt…)
- Скачивание с распаковкой: Flibusta отдаёт fb2/txt/rtf/html в zip — бот достаёт внутренний файл, чтобы читалка его открыла
- Дневные лимиты (скользящие 24 ч): 5 скачиваний, 20 поисков; список безлимитных ID
- Аналитика в SQLite (`/stats`), кэш поиска в памяти (6 ч)
- Неблокирующие обработчики + семафоры конкурентности

## Как используется LLM

Один вызов на каждый некэшированный поиск — `parseQuery`: текст → `{authors, title, series, genre}`. Всё остальное (OPDS-поиск, ранжирование, скачивание) детерминированно. Если LLM упал или таймаутит (15 с), бот деградирует до поиска по сырому названию. Thinking выключен ради скорости. Кэшированные запросы не делают ни одного вызова LLM.

## Требования

- Node 20 (рекомендуется через Docker)
- Токен бота Telegram (@BotFather)
- API-ключ z.ai (https://z.ai)
- Сервер/VPS с Docker

## Конфигурация

```bash
cp .env.example .env
```

| Переменная | Обяз. | По умолч. | Описание |
|---|---|---|---|
| `BOT_TOKEN` | да | — | токен @BotFather |
| `ADMIN_IDS` | да | — | Telegram ID админов (через запятую), видят `/stats` |
| `ZAI_API_KEY` | да | — | ключ z.ai |
| `ZAI_BASE` | да | — | эндпоинт z.ai, напр. `https://api.z.ai/api/paas/v4` |
| `MODEL` | да | — | модель, напр. `glm-4.5-air` |
| `FLIBUSTA_BASE` | да | — | зеркало Flibusta, напр. `https://flibusta.is` |
| `FLIBUSTA_FALLBACK_BASE` | нет | — | запасное зеркало |
| `ALLOWED_IDS` | нет | (пусто) | whitelist; пусто — бот публичный |
| `UNLIMITED_IDS` | нет | — | ID без дневных лимитов |
| `DOWNLOAD_DAILY_LIMIT` | нет | 5 | скачиваний за 24 ч |
| `SEARCH_DAILY_LIMIT` | нет | 20 | поисков за 24 ч |
| `RATE_LIMIT_PER_MIN` | нет | 20 | запросов в минуту на пользователя |
| `MAX_QUERY_LEN` | нет | 100 | макс. длина запроса, символов |
| `SEARCH_CACHE_TTL_SEC` | нет | 21600 | TTL кэша поиска |
| `LOG_TTL_DAYS` | нет | — | срок хранения событий, дней |

## Запуск (Docker)

```bash
docker compose up -d --build
docker compose logs -f
```

## Деплой на VPS

В `deploy.sh` указать `VPS=user@host`, затем:

```bash
./deploy.sh
```

Синхронизирует код по ssh, собирает образ, перезапускает контейнер.

```bash

npm test

```

## Архитектура

- **bot.ts** — обработчики grammY (long polling), неблокирующие: дорогая работа уходит в фон, очередь апдейтов не стоит.
- **orchestrator** — поиск: кэш → разбор LLM → OPDS-поиск → детерминированный ранг → топ-N.
- **search/llm.ts** — клиент z.ai, только `parseQuery`.
- **search/flibusta.ts** — обёртка над npm-пакетом `flibusta`: OPDS-поиск, нормализация метаданных.
- **download.ts** — скачивание во tmpfs + распаковка zip-обёртки.
- **db.ts / analytics.ts** — журнал событий SQLite и дневные лимиты.

## Правовые аспекты

Flibusta содержит книги с разным статусом авторских прав в зависимости от юрисдикции. Убедитесь, что имеете право скачивать контент в вашей юрисдикции. LLM-провайдер и модель настраиваются — соблюдайте условия использования выбранного провайдера.
